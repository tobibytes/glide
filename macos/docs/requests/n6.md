# N6 (Workflows, Automations) — notes for other sessions

## Workflow actions from your feature (no shared-file change needed)
Everything lives in GlideFeatures, so any feature can add workflow actions from `start(context:)`:

```swift
WorkflowActionRegistry.shared.register(feature: id, FeatureWorkflowAction(
    id: "start", title: "Start Timer", description: "…", emoji: "⏱️", symbol: "timer", category: .system,
    params: [WorkflowParamSpec("duration", "Duration", placeholder: "25m", required: true)],
    outputVar: nil) { params, vars in
        // params are {{var}}-substituted; throw WorkflowStepError("…") to fail the step
        return FeatureActionOutput(result: "Timer started")
    })
```
Stored form is the Electron one: `{type:"feature", params:{feature, action, …}}`. Your registration
replaces N6's host default for the same `<feature>.<action>`.

## Host defaults N6 registers (mirrors src/main/workflows/builtin-actions.ts)
- `transforms.<id>` for every `TextTransforms.all` entry (calls `TextTransforms.apply` directly).
- `timers.start` → `callFeature("timers", "start", {"ms": Int, "name": String})` — please accept that shape.
- `layouts.restore` → `callFeature("layouts", "state")` (expects `{layouts:[{id,name}]}`) then
  `callFeature("layouts", "restore", {"id": String})`.
- `ocr.captureText` → file source uses `services.ocr.recognize` directly; screen source calls
  `callFeature("ocr", "captureText", {})` (expects a string or `{text}`), never in headless.
- `convert.convert` → `context.search(query)` first row with `item.feature == "convert"` (text / data.copy).
- `automations.runNow` (own feature).
Results that are `{ok:false,error}` fail the step; `{message}` becomes the result.

## Wished for
- Settings sub-routes (`workflows/<id>`, `automations#new`) are not passed to `SettingsPage.view`; N6 keeps the
  requested selection inside the feature as a workaround. A `SettingsPage.view(route:)` would be cleaner.
- `SystemScriptService.runShell` reads pipes only after exit (can deadlock on >64 KB output) and is not a login
  shell; N6 uses its own `LoginShellRunner` when not headless.
- A way for features to record into the headless SideEffectLog (N6 prints its own `[headless] …` lines for
  http / sound / AppleScript-free effects via a private SideEffectLog).
- LauncherView footer `contextTitle` shows the raw view id for pushed feature views ("workflows.prompt");
  a `LauncherViewHost.setContextTitle(_:)` would let features name their views.
- `GlideDriver.defaultBinary()` does not find the binary under swift-testing (no .xctest in Bundle.allBundles);
  N6 driver tests run with `GLIDE_BINARY=<scratch>/debug/Glide` and skip when no binary is found.
