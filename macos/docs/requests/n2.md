# N2 (Clipboard History, Paste Stack, Snippets 2.0, pasteboard watcher, key-tap event hub): shared-file notes

## Keyboard tap: who configures it and how events reach N2
- `KeyboardFeature` (N3, `Sources/Features/Keyboard`) owns the one `services.keyboardTap.configure` call and the tap's
  single `onEvent` closure (lead decision). N2 does not call `configure`.
- N2 contributes through it:
  - `callFeature("keyboard", "setSnippets", [{keyword, text, id|null, excludedBundleIds}])` from Snippets 2.0. The
    list already has the keyword prefix and case variants applied, `text` holds the pre-rendered fallback, and `id`
    is set only for snippets that need a live render (placeholders, `{cursor}`, rich text). The global "no expansion
    in" apps are merged into each entry's `excludedBundleIds`.
  - `callFeature("keyboard", "setPasteStack", Bool)` from Clipboard: true only while the stack has items AND the
    "⌘V pastes the next item" setting is on. An empty or switched-off stack never intercepts ⌘V.
  - `callFeature("keyboard", "setExpandSnippets", Bool)` for the expansion switch in the snippet editor.
- Event hook: `KeyboardTapComposer` (`Sources/GlideSystem/Native/KeysComposer.swift`) fans tap events out to
  subscribers. **One-line edit in `KeyboardFeature.start`** (please keep): its `onEvent` closure first calls
  `KeyboardTapComposer.shared(for: services).dispatch(e)`. Snippets 2.0 subscribes for `.snippetMatched`: it renders
  in-process and calls `tap.finishExpansion`. Clipboard subscribes for `.stackNext`: it calls `tap.applyStackReply`,
  and if the 500 ms watchdog already fired (`applied == false`), it puts the item back at the head.
- `KeyboardTapComposer.merge` (pure) is still there for anyone who needs to combine several config parts.

## Other small additive edits (please keep)
1. `Sources/Features/UserContent/UserContentFeatures.swift` (`SnippetsFeature`): two static hooks.
   - `useHook`: Paste, Copy and Edit on `snippet:<id>` rows render placeholders, rich text and `{cursor}` through
     Snippets 2.0.
   - `settingsHook`: the Settings "Snippets" page shows the Snippets 2.0 editor.
2. `Sources/Features/AllFeatures.swift`: `ClipboardFeature()` (id `clipboard`) and `Snippets2Feature()` (id `snippets2`;
   it reads and writes the Electron bags `settings.features.snippets` and `.keyboard.expandSnippets`).
3. `Package.swift`: test target `N2FeatureTests`.
4. New GlideSystem files (N2-owned): `Native/PasteboardWatcher.swift` (`PasteboardWatching`,
   `SystemPasteboardWatcher`, `PasteboardWatcherFactory`), `Headless/FakePasteboardWatcher.swift`,
   `Native/KeysComposer.swift` (`KeyboardTapComposer` hub, `SyntheticKeys.paste(text:html:cursorLeft:services:)`).
   `Keys.swift`, `KeysLogic.swift` and `KeysSelfTest.swift` are unchanged; the selftest table still passes in
   GlideSystemTests.

## Wished for (not done)
- `PasteboardService` with rich read/write (HTML, RTF, images, files). Today rich content goes through
  `PasteboardWatcherFactory.watcher(for: services)`. N7 asked for the same thing (image read for OCR); both could
  use the watcher's `read()` and `write(_:)`.
- `LauncherViewHost.setQuery(_:)`, so "Search Snippets" with an argument and "Show in Clipboard History" can
  pre-fill the field.
- The launcher footer's context title shows the raw view id (`clipboard.history`). A `setTitle` on
  `LauncherViewHost` would allow "Clipboard History".
- Settings sub-routes (`snippets/<id>`) are not passed to `SettingsPage.view`. N2 works around it: the editor
  model remembers the snippet to select before `openSettings`.
- A text editor inside the launcher panel only works because the edit view forwards key events to its
  NSTextView itself (`ClipEditModel.handleKey`). The launcher reserves every key for feature/vim handling first.
